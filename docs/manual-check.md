# 手動確認チェックリスト

Phase 3（`@supabase/ssr` 一括移行）と Phase 5（権限別コンポーネント統合）の検証に使う。ユニットテストでは捕まらない失敗モード、特に **RLS がサイレントに 0 行を返す**（エラーなし・画面は空のまま描画される）を、権限クラスごとに確認する。

## 前提

- 確認用に、各ロールの Google アカウント（`@future-tech-association.org`）でログインできること
- データが空だと「RLS で見えない」と「本当に 0 件」を区別できない。**確認前に次が 1 件以上あること**
  - `public` ユーザー自身が作成した案件（下書きと経理申請中を 1 件ずつあるとよい）
  - 同じチームの別ユーザーの案件（teamleader 用）
  - 別チームの案件（teamleader には見えてはいけない）
  - 経理追加収支・定期費用マスタの行（accounting / admin 用）
- ブラウザの開発者ツール Network で、対象 API が 200 かつ配列が空、になっていないかを補助的に見る。画面上は「スピナー後に空」でもエラーは出ない

## 記号

- **表示**: ページが開き、想定どおりデータ行が見える
- **空でない**: 前提データを置いたうえで、一覧・表が 0 件のままにならない
- **拒否**: `/` へリダイレクト、または未ログインなら `/login`
- **対象外**: ナビに出ない / ロール的に開けない

## 案件詳細モーダル（Phase 5 で統合する箇所）

同一案件を、許可されたロールで開いたときに **案件名・金額・取引先・コストが空欄にならない** こと。ssr 移行後にモーダルだけ 0 件になる事故をここで拾う。

| 操作                                       | public         | teamleader       | accounting        | admin |
| ------------------------------------------ | -------------- | ---------------- | ----------------- | ----- |
| `/matters` から自分の案件を開く            | 表示（編集可） | 同左             | 同左              | 同左  |
| `/team` から他メンバーの自チーム案件を開く | 対象外         | 表示（参照中心） | 対象外            | 表示  |
| `/accounting` から任意案件を開く           | 対象外         | 対象外           | 表示（経理用 UI） | 表示  |

## Phase 3（ssr 移行）で特に見る点

1. ログインできる（Cookie 形式変更の切り分け）
2. 上表で「空でない」と書いたページが、移行前と同じ件数に見える
3. 経理ページでフィルタ → テーブル / カード / モバイル幅でも絞り込みが残る（#37 PR 1-a）
4. Auth 障害時に全員が `/login` へ飛ばされず、一時的なら 503 になること（再現できなければスキップ可）

## Phase 5（権限別 UI 統合）で特に見る点

1. public / teamleader / accounting で、統合前と同じ項目が同じ権限で編集・参照できる
2. accounting 専用の確認完了・Slack 通知が public に出ない
3. 読み取り専用モーダルを開いた teamleader で、保存ボタンから更新できてしまわない
