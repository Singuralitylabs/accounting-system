# 機能設計書

## 1. システム概要

### 1.1 システム名

経理システム

### 1.2 目的

未来技術推進協会のための案件処理、経理処理、取引先管理を効率化するウェブアプリケーション。

### 1.3 対象ユーザー

- 一般ユーザー: 案件作成・管理を行うメンバー
- チームリーダー: 自分のチームの案件を管理するメンバー
- 経理担当者: 案件の確認・承認を行うユーザー
- 管理者: システム全体の管理を行うユーザー

## 2. システムアーキテクチャ

### 2.1 開発環境

- フレームワーク: Next.js (App Router)
- 言語: TypeScript
- UI: Tailwind CSS, Mantine UI
- データベース: PostgreSQL (Supabase)
- 認証: Supabase Auth (Google OAuth)
- ホスティング: Vercel

### 2.2 システム構成

```
Frontend (Next.js) <--> Server (Next.js API Routes) <--> Database (Supabase)
```

### 4.16 月次損益計算書表示 (F017)

#### 4.16.1 概要

- 月を選択すると、その月の損益計算書を表示する
- 月次損益はスプレッドシート運用と同じ「粗利 → 管理費 → 経常利益」の構造で表示する
- 計算式:
  - **売上総利益（粗利） = 売上合計 − 案件費用合計**
  - **経常利益 = 粗利合計 − 管理費合計**（＝ 売上合計 − 案件費用合計 − 管理費合計）

#### 4.16.2 計上ルール（発生主義）

| 区分         | 計上月の判定                                                     | 金額                                                                                                   |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 売上         | business.invoice_date（請求日）の属する月                        | business.amount                                                                                        |
| 案件費用     | costs.period（支払い期限）の属する月                             | costs.price                                                                                            |
| 管理費       | 定期費用マスタの支払月（適用期間内かつ支払サイクルに一致する月） | recurring_costs.price（支払月に全額計上）                                                              |
| 経理追加収支 | extra_entries.entry_date（日付）の属する月                       | 収入の請求額（billing_amount）は売上合計へ、経費（expense_amount。収入・支出共通）は案件費用合計へ算入 |

- 月の判定は日付文字列の先頭 7 文字（YYYY-MM）の比較で行う（タイムゾーン変換による月ズレを避けるため Date オブジェクトは使わない）
- invoice_date / period / entry_date が NULL のレコードは「月未確定」として売上・費用の合計を別枠表示する
- business.amount は NULL 許容のため、集計時は NULL を 0 として扱う
- 定期費用の計上判定: 適用期間内（`start_month <= 選択月の月初日 AND (end_month IS NULL OR 選択月の月初日 <= end_month)`。end_month の月**を含む**）かつ支払月に一致する月
- 支払月は適用開始月を起点に支払サイクル間隔ごとに自動計算する（月払い=毎月、四半期払い=3ヶ月ごと、年払い=12ヶ月ごと）。月割り按分は行わず、支払月に全額計上する
- 経理追加収支はマイナス金額を許容する（案件側のデータを直さずに損益計算書上で減額調整するため）。収入の請求額は分類別売上内訳へ、経費は分類別に費用内訳へそれぞれ合算する

##### 分類別粗利の振り分けルール

粗利は売上分類（大分類）別に集計する。売上・案件費用はいずれもちょうど1つの分類に属するため、分類別粗利の合計は「売上合計 − 案件費用合計」と必ず一致する。

| 対象                       | 集計する分類                             |
| -------------------------- | ---------------------------------------- |
| 売上（business）           | 案件の分類（matters.category）           |
| 案件費用（costs）          | 案件の分類（matters.category）           |
| 経理追加収支の請求額・経費 | エントリの分類（extra_entries.category） |

- 売上のない分類に費用のみが計上された場合（支出エントリなど）は、粗利がマイナスの行として表示する
- 分類の値はマスタ（select_options）に追従し、特定の分類項目には依存しない。小分類別の集計は行わない（大分類まで）
- 管理費は費目（recurring_costs.item。select_options の item と同じ値域）別に集計する

#### 4.16.3 表示内容

- 損益計算書テーブル
  - 売上合計（分類別内訳をインデント行で表示。経理追加収支の収入（請求額）も分類別に合算する）
  - 案件費用合計（品目別内訳。各品目行は展開可能で、案件別明細＋「案件を表示」ボタンを表示。経理追加収支の経費も分類別に合算し、展開明細では内容＋「経理追加」表示の行とする＝「案件を表示」ボタンなし）
  - 売上総利益（粗利）（分類別内訳をインデント行で表示。各行に内訳として「売上 − 案件費用」を併記。マイナスは赤字表示）
  - 管理費合計（費目別内訳。各費目行は展開可能で、定期費用の明細（名称・チーム［未指定は「全体共通」と表示］。支払サイクルは月払い以外の場合のみ併記）を表示）
  - 経常利益（太字。マイナスは赤字表示）
- サマリーカード（売上 / 案件費用 / 粗利 / 管理費 / 経常利益）
- 経理追加収支セクション（選択月の明細一覧を全閲覧者に表示。経理担当者・管理者には経理追加収支画面（/extra-entries）への管理リンクを表示する）
- チーム別内訳（経理担当者・管理者のみ。列は 売上 / 案件費用 / 粗利 / 管理費 / 経常利益。チームに紐づかない管理費・経理追加収支は「全体共通」として表示）
- 全体共通（参考）セクション（チームリーダーのみ。全体共通の管理費・経理追加収支を参考表示し、チーム損益には算入しない）
- 月未確定の注記（該当データがある場合のみ。経理追加収支の日付未入力分を含む）

「案件を表示」ボタンは閲覧専用の案件詳細モーダル（`MatterCardDetail` の `variant="readonly"`）を開く。案件の閲覧可否は RLS により担保される。

#### 4.16.4 権限によるスコープ

| 権限               | 表示範囲                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------- |
| accounting / admin | 全案件・全定期費用・全経理追加収支。チーム別内訳あり                                     |
| teamleader         | 自チームの案件・自チーム向け定期費用・経理追加収支のみ損益に算入。全体共通は参考表示のみ |

### 4.17 年間推移表示 (F018)

#### 4.17.1 概要

- 年度（**7月〜翌6月**）を選択すると、12ヶ月分の損益推移を一覧表示する
- 「2026年度」= 2026年7月〜2027年6月
- 列: 7月〜翌6月の12ヶ月＋年度合計、行: 売上 / 案件費用 / 粗利 / 管理費 / 経常利益

### 4.18 定期費用マスタ管理 (F019)

#### 4.18.1 概要

- 定期的にかかる管理費（家賃・システム利用料など）を登録・管理する
- 支払サイクル（月払い / 四半期払い / 年払い）に対応し、支払月の損益計算書に支払額が全額算入される
- 実レコードは生成しない（適用期間と支払サイクルから計算で算出するため、登録・変更が即座に全期間へ反映される）

#### 4.18.2 登録項目

| 項目          | 説明                                               | 必須 |
| ------------- | -------------------------------------------------- | ---- |
| 名称          | 例: オフィス家賃                                   | ○    |
| 品目          | 品目マスタ（select_options の item）から選択       | ○    |
| 支払額（1回） | 円。支払サイクル1回あたりの金額（年払いなら年額）  | ○    |
| 支払サイクル  | 月払い / 四半期払い / 年払い（既定: 月払い）       | ○    |
| チーム        | チームマスタから選択。未選択 = 「全体共通」        | -    |
| 適用開始月    | 最初の支払月。以降はサイクル間隔ごとに支払月となる | ○    |
| 適用終了月    | この月まで損益に算入する（含む）。未設定 = 継続中  | -    |
| コメント      | 備考                                               | -    |

#### 4.18.3 機能

- 定期費用一覧表示・追加・編集・削除
- 一括保存（マスタデータ管理と同じステージング編集方式）

#### 4.18.4 金額改定の運用

月額が改定された場合は、既存行の適用終了月を改定前月に設定して打ち切り、新しい金額の行を改定月から新規登録する。これにより過去の月の損益計算書が遡って変わることを防ぐ。

#### 4.18.5 画面

- 定期費用マスタ画面 (/recurring-costs)

### 4.19 経理追加収支管理 (F020)

#### 4.19.1 概要

- 損益計算書は案件管理と定期費用マスタのデータだけでは実際の収支と必ずしも一致しないため、案件に紐づかない収入・支出を経理担当者・管理者が自由に登録・編集できるようにする
- 収入エントリは「請求額 → 売上」「経費 → 費用」の両方を計上できる（例: 受託収入とその外注費をセットで記録）。支出エントリは経費のみを計上する
- 登録したエントリは日付（entry_date）の属する月の損益計算書に算入される。日付未入力は「月未確定」として別枠表示する
- マイナス金額を許容し、案件側のデータを直さずに損益計算書上で差異の減額調整ができる

#### 4.19.2 登録項目

| 項目       | 説明                                                                               | 必須        |
| ---------- | ---------------------------------------------------------------------------------- | ----------- |
| 種別       | 収入 / 支出                                                                        | ○           |
| 分類       | 収入時は収入分類マスタ、支出時は支出分類マスタから選択（種別で選択肢が切り替わる） | ○           |
| 日付       | カレンダー入力。損益計算書に算入する月の判定に使用。未入力 = 月未確定              | -           |
| 請求書番号 | 自由入力。**収入時のみ**                                                           | -           |
| 内容       | 自由入力。過去に入力した値をサジェスト表示する                                     | ○           |
| 請求先     | 自由入力。過去に入力した値をサジェスト表示する。**収入時のみ**                     | -           |
| 責任者     | メンバー（profiles）から選択                                                       | ○           |
| チーム     | チームマスタから選択。未選択 = 「全体共通」                                        | -           |
| 請求額     | 円・税別。マイナス可・0 不可。**収入時のみ**                                       | ○（収入時） |
| 経費       | 円・税別。マイナス可・0 不可。収入時は任意（収入に紐づく経費）、支出時は必須       | ○（支出時） |
| 決済方法   | 決済方法マスタから選択。**支出時のみ**                                             | ○（支出時） |

#### 4.19.3 機能

- 経理追加収支画面（/extra-entries）で一覧表示・追加・編集・削除（ステージング編集方式・一括保存。マスタデータ管理・定期費用マスタと同方式）
- 分類（収入分類 / 支出分類）・決済方法の選択肢は、マスタデータ管理（F016。管理画面 /dashboard）で編集する
- 内容・請求先の入力欄は、登録済みエントリの過去の入力値をサジェスト候補として表示する
- 編集は経理担当者・管理者のみ。チームリーダーには損益計算書上で明細の閲覧のみ許可する（自チーム向け＋全体共通）

#### 4.19.4 損益計算書への反映

- 収入エントリ: 請求額を売上合計（分類別内訳）へ、経費（入力時のみ）を案件費用合計（分類別）へ算入
- 支出エントリ: 経費を案件費用合計（分類別）へ算入
- 分類別粗利では、請求額・経費ともにエントリの分類（収入分類 / 支出分類）の行へ算入する（[4.16.2](#4162-計上ルール発生主義) の振り分けルール参照）。支出エントリは売上のない分類となるため、粗利がマイナスの行として表示される
- 計上月は日付の属する月。日付未入力は「月未確定」として別枠集計する
- チーム別内訳にも算入する（チーム未指定は「全体共通」）

#### 4.19.5 画面

- 経理追加収支画面 (/extra-entries)
- 損益計算書画面 (/profit-loss) 内の経理追加収支セクション（明細表示＋管理リンク）

### 4.20 事前収支申告 (F021)

#### 4.20.1 概要

- 各チームのチームリーダーが、翌月のチーム収支（見込み収入・見込み支出）を明細付きで申告する
- 申告期限は毎月20日（当月20日までに翌月分を申告）。期限は未申告リマインドのトリガーであり、期限後の申告・修正も可能（DB / UI ではロックしない）
- 閲覧・編集はチームリーダー・経理担当者・管理者のみ。チームリーダーは自チーム分のみ
- 1 チーム × 1 対象月につき申告は 1 件（`budget_declarations` の UNIQUE 制約）。合計金額はヘッダに持たず明細から集計する

本節は Step 2（一覧ビュー）までの仕様である。申告の作成・編集フォームおよび未申告 Slack リマインドは後続ステップで追加する。

#### 4.20.2 申告項目

| 項目       | 説明                                                     | 必須 |
| ---------- | -------------------------------------------------------- | ---- |
| 対象月     | 申告対象の月（月初日で保持）。一覧の初期表示は翌月       | ○    |
| チーム     | チームマスタの値。チームリーダーは自チームのみ           | ○    |
| 申告者     | 最終更新したメンバー（`declared_by`）                    | ○    |
| コメント   | 補足コメント（自由入力）                                 | -    |
| 明細：種別 | 収入 / 支出                                              | ○    |
| 明細：分類 | 収入は案件分類マスタ、支出は品目マスタ                   | ○    |
| 明細：内容 | 自由入力（例: ○○受託案件、外注費）                       | ○    |
| 明細：金額 | 見込み金額（円・税別）。正の値のみ（符号は種別が決める） | ○    |

#### 4.20.3 一覧ビューの機能

- 対象月を月ピッカーで選択する。初期表示は JST 基準の翌月
- 対象月のチーム × 申告状況（申告済み / 未申告）を一覧表示する
  - チームリーダー: 自チームのみ。経理担当者・管理者: 全チーム
  - 未申告のチームも行として並べる（未申告の可視化が目的のため、申告のあるチームだけを並べない）
  - チームマスタから外れた（無効化・改名された）チームの申告も末尾に表示し、取りこぼさない
- 各行に収入合計・支出合計・差引（収入合計 − 支出合計）を表示し、表示中の行の合計を合計行に表示する
- 行を開くと申告明細（種別・分類・内容・金額）とコメントを参照表示する（この段階では編集不可）
- 申告者名は `profiles` の RLS で読めない場合に「-」表示となる（申告状況・集計はそのまま表示する）

#### 4.20.4 画面

- 事前収支申告画面 (/budget-declarations)

  - 支出エントリリスト（ステージング編集方式・一括保存）
    - 分類（支出分類） / 日付（カレンダー入力・クリア可） / 内容（サジェスト付き） / 責任者（メンバー選択） / チーム（選択。「全体共通」あり） / 経費（税別） / 決済方法 / 削除ボタン
    - 支出追加ボタン
  - 保存ボタン（収入・支出共通で一括保存）
- 日付のカレンダーはポータル表示とし、テーブルの横スクロール領域にクリップされないようにする

#### 5.3.13 トップページ (S013)

- URL: /
- ログイン中のロールでアクセスできるページの一覧（ナビゲーションハブ）
- 構成要素
  - ページタイトル「ページ一覧」
  - カードグリッド（アイコン・ページ名・説明文）
    - 権限のないページのカードは表示しない（ヘッダーナビと同じ `visibleNavItems` によるフィルタ）
    - 案件カードを先頭に配置し、従来のトップページからの導線を維持する
- ヘッダーはアプリ名とユーザーメニューのみ（ナビメニューは非表示）

#### 5.3.14 事前収支申告画面 (S014)

- URL: /budget-declarations
- 構成要素
  - ページタイトル「事前収支申告」
  - 対象月ピッカー（初期値は翌月）
  - チーム別申告状況テーブル
    - チーム / 申告状況（申告済み・未申告バッジ） / 収入合計 / 支出合計 / 差引 / 申告者 / 最終更新 / 明細表示ボタン
    - 未申告のチームは金額欄を「-」とし、明細表示ボタンを無効化する
    - 差引がマイナスの行は金額を赤字で表示する
    - 合計行に表示中のチームの収入合計・支出合計・差引を表示する
  - 明細パネル（行を開いたときのみ取得・表示）
    - 種別 / 分類 / 内容 / 金額、コメント（参照のみ）
    - 明細が 0 件の申告でもコメントは表示する（DB は明細 0 件のヘッダを許容する）

## 8. セキュリティ設計

### 8.1 認証

- Supabase Auth を使用した Google OAuth 認証
- 未来技術推進協会のドメイン(`future-tech-association.org`)のみログイン可能
- ミドルウェアによる保護されたルートの制御
  - /, /new, /matters: 認証済みユーザーのみアクセス可能
  - /team: チームリーダー・管理者のみアクセス可能
  - /accounting: 経理担当者・管理者のみアクセス可能
  - /dashboard: 管理者のみアクセス可能
  - /profit-loss: チームリーダー・経理担当者・管理者のみアクセス可能
  - /recurring-costs: 経理担当者・管理者のみアクセス可能
  - /extra-entries: 経理担当者・管理者のみアクセス可能

### 8.2 認可

- Row Level Security (RLS)によるデータアクセス制御
  - 一般ユーザー: 自身の案件のみアクセス可能
  - チームリーダー: 自分のチームの案件にアクセス可能
  - 経理担当者: 全案件のアクセス・更新が可能
  - 管理者: 全データのアクセス・更新・削除が可能
- ユーザー権限に基づく UI 制御
  - ナビゲーションメニューの表示/非表示
  - トップページのハブカードの表示/非表示（権限のないページは出さない）
  - 操作ボタンの表示/非表示

### 8.3 セキュアな通信

- HTTPS 通信のみ使用
- 環境変数による機密情報の保護
  - SLACK_WEBHOOK_URL: Slack 通知用 Webhook URL
