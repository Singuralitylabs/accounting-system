# 本番カットオーバー手順（accounting-system への一本化）

このドキュメントは Issue #61 の運用作業をリポジトリ側に手順化したものである。  
ローカル識別子の変更（`supabase/config.toml` の `project_id`）とは独立しており、**本番データの切り替え作業そのものはダッシュボード権限が必要**である。

## 現状（前提）

- GitHub リポジトリ名とローカル Supabase `project_id` は `accounting-system`
- 本番は **旧 Vercel プロジェクト** と **新 Vercel プロジェクト（accounting-system）** が別々に稼働している
- それぞれに対応する **本番 Supabase プロジェクトも 2 つ**ある
- 協会の利用者が実際にログインして使っているのは **旧プロジェクト側**
- 新プロジェクト側はスキーマ・データの同期済みスナップショットがあるが、旧側はカットオーバーまで書き込みを受け続ける

プロジェクトの正式な旧ホスト名は Issue #61 を参照する（本リポジトリの識別子 grep 方針のため、ここでは再掲しない）。

## この環境から実施できないこと

Cloud Agent / 開発コンテナからは次ができない。担当者が Vercel・Supabase・Google Cloud の本番コンソールで実施する。

- [ ] Vercel の本番環境変数が **新** Supabase（URL / anon key / service role 等）を指していることの確認
- [ ] Google OAuth のリダイレクト URI、Supabase Auth の Site URL / Redirect URLs に **新ドメイン** が登録済みであることの確認
- [ ] 旧 Supabase → 新 Supabase の **カットオーバー直前の差分データ移行**
- [ ] 書き込み停止を伴うメンテナンス時間の確保と、利用者への新 URL・時刻の周知
- [ ] 切替後のログイン・案件操作・Slack 通知の本番確認
- [ ] 旧環境の読み取り専用化、一定期間の並行監視、バックアップ取得後の廃止
- [ ] 問題発生時に旧環境へ戻すロールバック（旧環境をすぐには廃止しない）

## カットオーバー手順

### 1. 切替前チェック（書き込み停止の前）

1. 新 Vercel（`https://accounting-system.vercel.app/`）の Environment Variables が、新 Supabase プロジェクトを指していることを確認する。
2. Google Cloud Console の OAuth クライアントに、新ドメインのコールバック URL があることを確認する。
3. 新 Supabase の Authentication → URL Configuration で Site URL と Redirect URLs が新ドメインになっていることを確認する。
4. 新 URL で **テストアカウント** が、本アプリの「ログイン / Google認証」画面から協会ドメインで入れることを確認する。2026-08-26 時点では新 URL が英語の汎用 Sign in（Vercel 保護または別認証）になっており、旧 URL 側だけが本アプリのログイン画面である。この差が残ったまま利用者を誘導してはならない。

### 2. メンテナンスと最終差分移行

1. 利用者へ切替日時と新 URL を事前周知する。
2. 旧本番の書き込みを止める（メンテナンス表示、または旧アプリを一時停止）。
3. 旧 Supabase から新 Supabase へ **差分を移行**する。以前の「同期済み」はスナップショットに過ぎない。切替直前までに発生した新規案件・更新を移さないと本番データが欠ける。
4. 移行後、件数・最新更新日時など、案件 / 取引先 / コスト / プロフィールの突合を行う。

### 3. トラフィック切り替え

1. 利用者を新 URL（`https://accounting-system.vercel.app/`）へ誘導する。
2. 旧 URL には「新環境へ移動」バナーを出す、または読み取り専用にする。周知不足だと旧環境（切替後は古いデータ）へ入力が続く。

### 4. 切替直後の確認

新 URL で少なくとも次を確認する。

- Google ログイン（協会ドメイン）
- 案件の一覧・作成・編集・経理申請
- Slack 通知
- 経理一覧・損益など権限付き画面

### 5. 監視・ロールバック・廃止

1. 旧環境はすぐ廃止しない。障害時は DNS / 案内を旧 URL に戻し、必要なら新側で入った差分を旧へ戻せるようにする。
2. 一定期間問題がなければ、旧 Vercel / 旧 Supabase のバックアップを取ってから廃止する。

### 6. カットオーバー完了後のリポジトリ更新

1. README の本番 URL を `https://accounting-system.vercel.app/` に書き換える（切替前は現行利用者が使う旧 URL のままにする）。
2. `grep -rn matter-controller` でリポジトリに旧識別子が残っていないことを確認する。

## リポジトリ側で完了済みのこと

- UI・ドキュメントのサービス名を「経理システム」に統一
- ローカル `project_id` と Docker コンテナ名例を `accounting-system` に変更
- カットオーバー手順の文書化（本ファイル）

ローカル `project_id` 変更後の再起動手順は [setup.md](./setup.md) の「project_id 変更後のローカル再起動」を参照する。`supabase db reset` では旧スタックを止められない。本番データには影響しない。
